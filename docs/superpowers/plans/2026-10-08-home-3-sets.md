# Home H3: New Sets and Saved Sets — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Home learns which sets watched DJs' searches found that you have not seen, and Customize's catalog gains the last two cards:
- **New sets** (Needs you, 2×2, min 2×1, max 4×3): the 20 newest unseen sets — title, "DJ · channel", "saved" or "5–7 units" — each opening the set in Sets; header link **Mark all seen**, with a toast and **Undo**; empty "No new sets".
- **Sets you saved lately** (Jump back in, 2×2, min 2×1, max 4×3): the 10 sets stored last — title, channel, when it was saved — each opening the set; empty "No saved sets yet".
- **Needs you** gains its **New sets** row (the count; "New sets by Hot Since 82" when they are all one DJ's), which opens Sets on its library.
- A set is **seen** once it is opened anywhere (Sets shows it); opening Sets alone marks nothing. Finds stored before this plan are marked seen once, so news starts with the next search.

**Architecture:**
- **Rust:** migration 018 adds `yt_dj_finds.seen_at` (NULL = unseen) and marks every stored find seen, once (a column check, as 011). `record_yt_dj_find` — the one place finds are written — writes a find already seen when its video is in `yt_sets` or another find of it is seen. `db/home.rs` gains `get_new_dj_finds(limit)` (distinct unseen videos, each under its first finder, newest first, with the total), `mark_dj_finds_seen(video_ids)`, `mark_all_dj_finds_seen()` (answers the `(name_key, video_id)` rows it changed, via `UPDATE … RETURNING`) and `mark_dj_finds_unseen(rows)`; `commands/home.rs` exposes the four.
- **Pure TypeScript** (tested): `lib/home/cards.ts` gains the two catalog entries (all 15 now); `lib/home/labels.ts` gains Needs you's New sets row, `newSetLine` and `newSetCost`.
- **App / Sets:** `SetsStart` gains `tab: 'library'` and SetsView an `initialTab`; SetsView marks a set's finds seen whenever it shows one (every way of opening a set ends there); the `yt-new-sets` handler raises `dataVersion` at its start and again after its auto-import; `handleMarkAllSetsSeen` marks, raises the number and shows the toast whose Undo marks those rows unseen and raises it again. HomeView gains `onOpenSet`, `onOpenSetsLibrary`, `onMarkAllSetsSeen`.
- **Components:** `useHomeData` reads `newSets` (New sets, Needs you) and `savedSets` (`listYouTubeSets()`, first 10); `HomeCards` draws the two cards with a shared `SetRow`, the Mark all seen link and Needs you's row; `HomeView.css` styles them.

**Spec:** `docs/superpowers/specs/2026-10-04-home-cards-design.md` (catalog table, "New sets" under Cards in detail, the Needs you table, Staying current, Data, Testing) and the Interactions spec's Undo table (Mark all seen). **Decisions, beyond the spec's letter** (Task 9 writes them into the spec):
- **Seen is marked in one place:** SetsView, whenever it shows a set (`currentSet` changes), calls `mark_dj_finds_seen([videoId])`. Home's rows, a DJ page's set cards, Search, YouTube Music's Open in Sets and Sets' own library, pasted links, search hits and Following all open sets there, so none of them needs its own call. A set whose fetch fails (no quota left) is not shown and stays new; auto-import stores sets without showing them, so an auto-imported set stays new, as the spec says.
- **Home's own raise** is needed only after Mark all seen and its Undo: Home gives way to Sets when it opens a set and reads everything again the next time it opens. App owns that raise and the toast (as the track table's Undo toasts), through `onMarkAllSetsSeen`.
- **The toast:** "4 sets marked seen" (distinct videos among the rows changed) with **Undo**; nothing changed, no toast. A failure says "Couldn't mark the sets seen: …" (error toast); a failed Undo "Couldn't undo: …".
- **Order:** newest first by each video's first find; videos found in the same second (one check stamps its rows alike) newest published first, then by id. A video found by two DJs' searches shows under the DJ whose find came first, on the same second the lowest name key.
- **Rows:** New sets — title over "DJ · channel" (the channel once when it is the DJ's own, e.g. "Hot Since 82" on Hot Since 82's channel), "saved" or "5–7 units" on the right. Sets you saved lately — title over the channel, and when it was saved as Recently added says it ("19:31", "yesterday", "Oct 5"). Titles and lines cut short show in full as a tooltip.
- **Needs you's row:** "New sets by Hot Since 82" (the mockup's line) when every unseen set was read (≤ 20) and all are one DJ's, else "New sets"; "New set" for one. Its number is the mockup's orange `#fb923c`, drawn toward the text colour as the others. It opens Sets on its **Library** tab (`SetsStart.tab`).
- **The DJ's name** comes from `yt_watched_djs` (the name as watched); unwatching a DJ already deletes their finds, so a find always has one — the name key stands in if not.
- **Migration 018** also indexes `yt_dj_finds(video_id)` (the seen checks look a video up across DJs).

    /// The videos none of whose finds is seen, newest first, at most `limit`,
    /// and how many there are in all. A video found by two DJs' searches is
    /// one, under the DJ whose find came first (on the same second, the lowest
    /// name key: one check stamps its rows alike); newest first is by that
    /// find, then by when the video was published.
    pub fn get_new_dj_finds(&self, limit: i64) -> Result<NewDjFinds> {
        const UNSEEN: &str = "SELECT video_id FROM yt_dj_finds GROUP BY video_id HAVING COUNT(seen_at) = 0";
        let total = self
            .conn
            .query_row(&format!("SELECT COUNT(*) FROM ({UNSEEN})"), [], |row| row.get(0))?;
        let mut stmt = self.conn.prepare(&format!(
            "WITH firsts AS (
                 SELECT f.*, ROW_NUMBER() OVER (
                     PARTITION BY f.video_id ORDER BY f.first_seen_at, f.name_key
                 ) AS n
                 FROM yt_dj_finds f
                 WHERE f.video_id IN ({UNSEEN})
             )
             SELECT f.video_id, f.name_key, COALESCE(w.display_name, f.name_key), f.title, f.channel,
                    EXISTS (SELECT 1 FROM yt_sets s WHERE s.video_id = f.video_id)
             FROM firsts f
             LEFT JOIN yt_watched_djs w ON w.name_key = f.name_key
             WHERE f.n = 1
             ORDER BY f.first_seen_at DESC, f.published_at DESC, f.video_id
             LIMIT ?1"
        ))?;
        let finds = stmt
            .query_map([limit], |row| {
                Ok(NewDjFind {
                    video_id: row.get(0)?,
                    name_key: row.get(1)?,
                    display_name: row.get(2)?,
                    title: row.get(3)?,
                    channel: row.get(4)?,
                    saved: row.get(5)?,
                })
            })?
            .collect::<Result<Vec<_>>>()?;
        Ok(NewDjFinds { total, finds })
    }

    /// Every find of these videos is seen from now on: their sets were opened.
    pub fn mark_dj_finds_seen(&self, video_ids: &[String]) -> Result<()> {
        let tx = self.conn.unchecked_transaction()?;
        for video_id in video_ids {
            tx.execute(
                "UPDATE yt_dj_finds SET seen_at = datetime('now') WHERE video_id = ?1 AND seen_at IS NULL",
                [video_id],
            )?;
        }
        tx.commit()
    }

    /// Mark all seen: every unseen find is seen. Answers the rows it changed,
    /// so an Undo marks exactly those unseen again.
    pub fn mark_all_dj_finds_seen(&self) -> Result<Vec<DjFindKey>> {
        let tx = self.conn.unchecked_transaction()?;
        let changed = tx
            .prepare(
                "UPDATE yt_dj_finds SET seen_at = datetime('now') WHERE seen_at IS NULL
                 RETURNING name_key, video_id",
            )?
            .query_map([], |row| {
                Ok(DjFindKey {
                    name_key: row.get(0)?,
                    video_id: row.get(1)?,
                })
            })?
            .collect::<Result<Vec<_>>>()?;
        tx.commit()?;
        Ok(changed)
    }

    /// Mark all seen's Undo: these rows are unseen again; no other is touched.
    pub fn mark_dj_finds_unseen(&self, rows: &[DjFindKey]) -> Result<()> {
        let tx = self.conn.unchecked_transaction()?;
        for row in rows {
            tx.execute(
                "UPDATE yt_dj_finds SET seen_at = NULL WHERE name_key = ?1 AND video_id = ?2",
                params![row.name_key, row.video_id],
            )?;
        }
        tx.commit()
    }
}
