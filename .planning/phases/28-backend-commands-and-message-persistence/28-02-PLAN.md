    1. **Change the function signature** (line 543) to add `conversation_id: Option<String>`:

       ```rust
       #[tauri::command]
       pub async fn ai_chat(
           state: State<'_, AppState>,
           message: String,
           conversation_history: Vec<ChatMessage>,
           conversation_id: Option<String>,
       ) -> Result<String, AppError> {
       ```

    2. **After the API key check (line 549) and before the library context logic (line 552), save the user message if conversation_id is present:**

       ```rust
       // Persist user message if conversation tracking is active
       if let Some(ref conv_id) = conversation_id {
           let db_guard = state.db.lock().map_err(|_| AppError::Internal("State lock failed".to_string()))?;
           if let Some(db) = db_guard.as_ref() {
               if let Err(e) = db.create_message(conv_id, "user", &message) {
                   eprintln!("[ai_chat] Failed to save user message: {}", e);
                   // Non-fatal: continue with AI call even if DB save fails
               }
           }
       }
       ```

       IMPORTANT: The DB lock is acquired and released in its own scope (the `if let` block). Do NOT hold the lock across the async Claude API call. The user message is saved with the original `message` text (before library context is prepended), so the stored content matches what the user actually typed.

    3. **After the Claude API response (line 594, after `let response = client.chat(...).await?;`), save the assistant message:**

       ```rust
       // Persist assistant response if conversation tracking is active
       if let Some(ref conv_id) = conversation_id {
           let db_guard = state.db.lock().map_err(|_| AppError::Internal("State lock failed".to_string()))?;
           if let Some(db) = db_guard.as_ref() {
               if let Err(e) = db.create_message(conv_id, "assistant", &response) {
                   eprintln!("[ai_chat] Failed to save assistant message: {}", e);
                   // Non-fatal: return response even if DB save fails
               }
           }
       }

       Ok(response)
       ```

    - DB save failures are logged but do NOT prevent the AI response from being returned
    - The `message` saved to DB is the raw user input, NOT the version with prepended library context
    - Auto-titling happens inside `db.create_message()` (implemented in Plan 01) -- no extra logic needed here

    Do NOT modify any other commands: `ai_generate_playlist`, `ai_generate_playlist_from_seed`, `ai_recommend_similar`, `ai_recommend_for_playlist`, `ai_optimize_playlist_order` all stay untouched (COMPAT-01).

