<task type="auto">
  <name>Task 2: Add Windows build.rs LIBCLANG_PATH hint and tauri.conf.json autoplay fix</name>
  <files>src-tauri/build.rs, src-tauri/tauri.conf.json</files>
  <action>
1. Update `src-tauri/build.rs` to add a Windows-only LIBCLANG_PATH fallback BEFORE the `tauri_build::build()` call:

```rust
fn main() {
    // On Windows, help bindgen find libclang if LIBCLANG_PATH is not set
    #[cfg(target_os = "windows")]
    {
        if std::env::var("LIBCLANG_PATH").is_err() {
            let default = r"C:\Program Files\LLVM\bin";
            if std::path::Path::new(default).exists() {
                std::env::set_var("LIBCLANG_PATH", default);
            }
        }
    }

    tauri_build::build()
}
```

The `#[cfg(target_os = "windows")]` block is completely inert on macOS — it does not compile at all. This is additive only.

2. Update `src-tauri/tauri.conf.json` to add `additionalBrowserArgs` to `app.windows[0]`:

Change:
```json
"windows": [
  {
    "title": "recodeck",
    "width": 800,
    "height": 600
  }
]
```

To:
```json
"windows": [
  {
    "title": "recodeck",
    "width": 800,
    "height": 600,
    "additionalBrowserArgs": "--autoplay-policy=no-user-gesture-required --disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection"
  }
]
```

CRITICAL: The `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection` flags MUST be included because Tauri/wry sets these by default, but providing `additionalBrowserArgs` overrides ALL default args. Without re-including them, WebView2 behavior changes. The `--autoplay-policy=no-user-gesture-required` flag fixes WebView2's autoplay block that prevents `audioPlayer.ts` from calling `.play()` without user gesture. This field is ignored on macOS (WebKitGTK/WKWebView don't read Chromium args).

Do NOT modify any other fields in tauri.conf.json.
  </action>
